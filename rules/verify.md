# 검증의 근거와 범위

## 기본 동작부터 시작한다

승인된 S#의 검증에 들어가거나 사용자가 테스트를 요청하면 이 절차를 적용한다. 사용자가 별도 스킬을 고르게 하지 않고 메인 세션이 검사와 이해를 함께 안내한다.

- 먼저 실제 요구에서 고른 대표 정상 입력으로 `입력 → 핵심 처리 → 사용할 결과`가 끝까지 이어지는지 확인한다. 서버 기동이나 화면 표시만으로 기본 기능을 확인했다고 하지 않는다. 기본 흐름이 막히면 그 경로부터 복구한다.
- 기본 흐름을 확인한 뒤 최종 요구와 대조해 빠진 요구·틀린 결과·미확인 중 다음 검사를 고른다. 상세 기능·경계·예외·규모·성능 검사는 실제 요구·위험과 남은 시간에 맞춰 확대한다. 검사 개수나 모든 도구의 사용을 완료 조건으로 삼지 않는다.
- 변경한 기능과 관련 회귀를 확인한다. 현재 변경에도 유효한 검사 결과는 재사용하며, 같은 기본 경로를 이유 없이 반복하지 않는다. 명령으로 확인할 검사는 verify.sh에 유지한다.

## 검사 전: 기준과 현재 경로를 보여 준다

- 지금 확인할 요구·주장, 기대 결과와 출처, 선택한 입력을 먼저 짚는다. 실제 입력 하나가 어느 지점에서 시작해 어디까지 지나고 어떤 값을 비교하는지 설명한다. 처음이거나 경로가 바뀌면 짧은 도식을 쓰고 같은 흐름은 재사용한다.
- 기대값은 앱 코드에서 가져오지 않는다. 자료를 별도로 집계한 값이나 파트너 답·예시에서 가져오고 출처를 남긴다.
- 검사 기준도 풀이 결과가 임의로 정하게 두지 않는다. 합의된 요구·설정의 출처와 버전을 별도로 대조한다. 검증 코드를 분리했어도 같은 잘못된 가정·전처리를 공유하면 독립 근거가 되지 않는다.
- AI 출력처럼 판단이 필요한 요구는 docs/evals.md의 케이스와 기대 반응으로 본다. 구조 검사는 스크립트로, 품질은 맞음·어긋남과 근거로 기록한다.
- Docker 등 실행 환경과 함수·서버 직접 요청·브라우저 같은 검사 경로를 구분한다. 빌드·기동·기능 확인, 대역·실제 구성요소, 코드에서 읽은 경로·실행해 관찰한 결과를 구별한다. 검사 코드가 요구에 연결된 값을 실제로 비교하는지도 살펴본다.

## 검사 중: AI의 실행과 사람의 행동을 연결한다

- AI가 실행한 검사와 아직 사람이 관찰할 부분을 구분한다. AI가 실행 가능한 승인된 검사는 직접 처리하고, 브라우저·화면 조작은 사람에게 맡긴다.
- 사람이 실행할 때는 실제 작업 폴더·명령·포트·미리보기 경로와 필요한 데이터 상태를 준비한다. 서버 실행 안내는 docs/state.md에 둔다. 현재 사례의 입력·조작 순서·관찰할 값과 각 행동의 이유를 함께 보여 준다. 이미 끝난 준비는 반복하지 않는다.
- 사람에게는 현재 사례부터 안내하고 실제 관찰을 기다린다. 다음 수동 사례를 연달아 쌓거나 미관찰 결과를 채우지 않는다. 화면이 기대와 다르면 처음 달라진 단계·실제 문구나 값을 받아 다음 확인을 좁힌다.
- localhost·외부 네트워크가 권한으로 막히면 필요한 승인을 요청하거나 사람에게 실행을 넘긴다. 서버를 안 띄운 경우도 따로 확인한다. 실행 차단·미실행과 실제 기능 실패를 구분한다.

## 검사 후: 기대와 실제를 대조하고 범위를 판정한다

- 입력·환경·실행 경로, 기대와 실제, 로그·관찰자를 연결해 확인된 주장과 남은 범위를 짧게 보고한다. 종료 코드나 성공 문구만으로 기능 정확성을 선언하지 않는다. 관련 검사가 없거나 실행하지 않았다면 검증 완료가 아니다. 기대값 근거가 없으면 미확인으로 남긴다.
- 통과는 실행한 입력·경로·조건에 대한 증거다. HTTP 검사와 사람의 화면 관찰을 구분하며, 한 검사의 통과로 다른 경로의 앱 오류를 제외하지 않는다. 기본 통과를 전체 요구 충족으로 확대하지 않는다.
- 기본 흐름 이후 필요한 경우 요구에 맞는 경계·실패 입력으로 잘못된 동작을 구별하는 검사인지 확인한다. 실패하면 원인 후보와 그 후보를 가를 다음 확인을 제시한다. 원인을 확인해 승인 범위에서 고치고, 미해결 영향은 보고한다. 실패 코드만으로 원인을 단정하지 않는다.
- verify.sh는 verify-cases.sh의 등록 검사를 실행하고 docs/verification 아래 실행별 표준 출력·오류·종료 코드를 보존한다. check_command에는 명령과 인자를 분리해 전달한다. 기존 check의 셸 문자열은 신뢰한 로컬 검사에만 사용한다. 기록할 출력에 개인정보·키가 들어가지 않도록 검사를 구성한다.
- 결과는 기존 docs/evals.md의 검사 ID별 주장·기대값·출처·확인 범위와 로그에 연결한다. 별도 결과 장부를 늘리지 않는다. 실행 로그는 기대값 출처나 기능 정확성을 대신하지 않는다.
- 이해가 막히면 현재 경로·기대값·판정 중 빠진 연결을 explain의 설명 방식으로 풀고, 다음 검사 선택이 문제면 현재 위험·시간을 기준으로 추천한다. 별도 스킬 호출을 사용자에게 떠넘기지 않는다. 중요한 결과 수용에는 toolkit/understanding.md를 적용하되 모든 명령마다 장문·그림·이해 시험을 반복하지 않는다.
- 승인한 범위 밖의 기능·라이브러리는 제안만 한다. 구현에 사용하는 미확인 가정은 A#로 연결한다. 역할 의견은 사용자가 채택한 내용만 반영한다.
