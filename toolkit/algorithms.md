# 알고리즘: 업무 기준을 입력·제약·결과로 바꾸기

언제: 결과를 계산·검색·배치·최적화하는 방법 선택이 정확성·시간·품질에 영향을 줄 때. 단순 입출력 기능에 최적화 문제를 억지로 만들지 않는다.

## 최소 지도

업무에서 원하는 결과 → 입력·출력 → 반드시 지킬 조건 → 좋은 결과의 기준 → 자료 크기 → 단순한 방법 → 필요한 개선.

## 사람이 판단할 것

- 반드시 만족해야 하는 조건과 더 좋으면 되는 목표를 구분한다.
- 답이 반드시 최선이어야 하는지, 충분히 좋은 답이면 되는지 확인한다.
- 익숙한 알고리즘 이름부터 고르지 않고 실제 입력 크기·제약·검증 가능성을 본다.
- 직접 구현·라이브러리·공개 레포 후보를 쓰면 어떤 계산을 맡기고 어떤 업무 규칙은 직접 확인해야 하는지 구분한다.

## 작은 적용

작은 가상 입력에서는 가능한 답을 모두 살펴 기대 결과나 조건 충족 여부를 확인할 수 있다. 큰 입력에서 그 방법이 느려질 수 있음을 구분한다. 빠른 방법을 택했다면 언제 최선이 보장되지 않거나 조건을 어길 수 있는지 실제 방법에 맞게 설명한다.

## 확인과 멈출 곳

작은 입력의 독립 기대값, 조건 위반 여부, 필요한 크기의 시간·결과 품질을 본다. 개선을 주장하면 같은 조건의 단순한 방법과 비교한다. 알고리즘 기초를 처음부터 강의하지 않고 현재 업무의 형식화·선택·검증에 집중한다.
