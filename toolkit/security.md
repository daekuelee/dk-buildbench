# 보안: 누가 무엇을 하면 안 되는가

언제: 권한·외부 입력·민감한 정보·외부 호출이 있는 경우 관련 범위를 선택한다. 모든 상황에 인증 시스템을 새로 만드는 절차가 아니다.

## 최소 지도

보호할 정보·행동 → 사용자와 권한 → 신뢰할 수 없는 입력 → 허용·거절 조건 → 결과·노출 확인.

## 사람이 판단할 것

- 누가 어떤 정보를 읽거나 바꿀 수 있는가. 실패하면 어떤 피해나 잘못된 업무 결과가 생기는가.
- 화면에서 버튼을 숨긴 것과 실제 요청을 거절하는 것은 무엇이 다른가.
- 외부 입력·파일·외부 서비스 결과를 어디서 검증하는가.
- 로그·오류·화면·외부 전송에 어떤 정보가 드러나면 안 되는가.

## 작은 적용

가상 요구에서 ‘본인 기록만 수정 가능’이라고 정했다면 다른 기록 식별자를 보내는 요청도 거절되어야 한다. 이 요구 자체를 모든 과제의 사실로 가져가지 않는다. 실제 권한 기준부터 확인한다.

## 확인과 멈출 곳

요구에서 정한 금지 동작을 안전한 시험 자료로 확인하고 응답·실제 상태·노출을 대조한다. AI 검토의 문제 없음 보고만으로 안전을 단정하지 않는다. 확인한 범위와 미확인 범위를 분리하고 중요한 위험에 우선순위를 둔다. 사람은 검사 코드 전체보다 보호 기준과 실제 확인 근거를 이해한다.

동작 오류를 해결하려고 보호 설정을 완화한다면 사라지는 보호와 대체 검증을 함께 판단한다. 한계를 문서에 적는 것만으로 위험이 해결되지는 않는다. 환경 확인은 필요한 비민감 항목만 출력하며 환경 변수·인증 설정 전체를 덤프하지 않는다.
