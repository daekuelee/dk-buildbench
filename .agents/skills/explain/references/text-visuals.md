# 렌더러 없이 읽는 그림

그림 하나가 답할 질문을 먼저 정한다. 코드 블록 안에서 짧은 이름·번호·화살표를 쓰며, 좁은 화면에서는 세로로 배치한다. 색·폰트·정교한 한글 열 정렬 없이도 뜻이 남아야 한다. 상자를 늘리기보다 입력·변화·실패·사람의 결정 위치를 드러낸다.

이 문서는 텍스트 환경을 위한 대체 표현이다. 풍부한 시각 페이지를 요청한 경우까지 고정폭 그림만 쓰라는 뜻이 아니다. 그때는 실제 SVG 도식으로 공간·시간·상태·비교 관계를 표현하고, 여기의 방법으로 같은 설명의 텍스트 경로를 제공한다.

## 동작과 실패를 함께 보기

가상 예시이며 특정 앱 요구가 아니다.

```text
[1 사람이 등록 요청]
        |
        v
[2 서버: 입력과 권한 확인] -- 거절 --> [저장하지 않고 이유 반환]
        |
        v
[3 저장 완료 확인] ------ 실패 --> [성공이라고 응답하지 않음]
        |
        v
[4 성공 응답] --> [5 다시 조회해 표시]
```

본문에서는 실제 값 하나로 1→5를 따라간다. 3과 4의 순서가 왜 필요한지, 어디까지 실행으로 확인했는지 연결한다. 파일명을 붙일 때는 읽어서 확인한 이름만 쓴다.

## 상태와 결정 주체 보기

```text
초안 -- 검사 통과 --> 검토 가능 -- 사람이 채택 --> 적용
  \-- 검사 실패 --> 보완 대기
```

화살표가 자동인지 사람의 선택인지 적는다. 상태 이름만으로 자동 공개나 승인 기준이 있다고 추정하지 않는다.

## 검사 결과의 경계 보기

```text
근거: 합의된 요구 + 외부 기대값
                 |
                 v
동일 입력 --> [실행한 경로] --> 관찰 결과
                 |
                 +--> 확인 안 한 경로: 별도 표시
```

그림 아래에 ‘확인된 주장 / 아직 말할 수 없는 주장’을 짧게 쓴다. 이때 이해 확인이 필요하면 현재 결과로 다음 행동을 고르게 한다. 정답을 먼저 쓰고 따라 말하게 하지 않는다.

## 길어졌을 때

업무 전체 지도와 현재 막힌 연결의 확대 그림을 분리한다. 현재 결정을 위한 핵심 문단은 펼친 상태로 두고 부차 근거만 뒤로 보낸다. Markdown 표가 넓어지면 항목별 세로 목록으로 바꾼다. HTML을 추가하더라도 같은 핵심 설명과 출처를 Markdown에 유지한다.
