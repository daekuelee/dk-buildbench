# 설명의 깊이를 고르는 기준

길이보다 현재 질문에 답하는 인과관계가 충분한지를 본다. 사용자가 모드를 고르게 하지 않고 대화·자료·이미 한 선택에서 필요한 수준을 판단한다. 깊이를 명시한 요청을 우선한다.

## 세 가지 상황

- **국소 확인:** 용어·경로·이미 정한 동작의 확인. 직접 답하고 그 답을 뒷받침하는 근거나 작은 예를 붙인다. 앱 전체를 다시 설명하지 않는다.
- **동작·선택 이해:** 중요한 개념이 낯설거나 결과가 달라지는 선택. 왜 필요한지 → 입력·상태·출력 그림 → 실제 값 한 번 → 실제 대안의 차이 → 현재 선택 기준. 형식을 모두 채우기보다 판단에 필요한 연결을 완성한다.
- **핵심 원리 심화:** 사용자가 깊이를 요청하거나, 결과는 외웠는데 왜 그런지 연결되지 않아 판단·실패 예측이 막힌 경우. 핵심 주장 하나를 잡고 전제·원인·단계·반례 또는 실패 경로까지 설명한다. 자료를 읽지 않았다면 조사 필요·가정을 표시한다. 핵심 단계를 ‘당연하다’로 건너뛰지 않는다.

전체를 이해하기 전에 한 부품의 내부로 내려가지 않는다. 현재 설명은 업무 흐름·앱 구조·저장 보장 중 어느 층인지 밝히고, 다른 층으로 내려갈 필요와 현재 질문의 연결을 설명한다. 관련 없는 내부 원리는 나중에 볼 이름과 이유만 남긴다.

## 그림과 본문의 역할

상세 구조 설명은 제목·짧은 문맥 뒤에 그림을 먼저 둔다. 이어 ‘그림이 보여 주는 것 / 본문에서 확인할 핵심 이유 / 읽을 부분’을 짧게 안내한다. 그림의 객체·화살표가 무엇인지 본문에서 실제 값으로 따라간다. 낯선 용어는 처음 등장할 때 정의한다. 깊이란 상자 수가 아니라 관계·실패 원인·통제를 설명하는 정도다.

현재 환경과 요청에 맞춰 그림을 고른다. 제한된 에디터에서는 [text-visuals.md](text-visuals.md)의 텍스트 흐름·분기·상태 표현을 사용하며 렌더링을 전제로 삼지 않는다. 시각 페이지를 요청하면 SVG 등 실제 구조 도식을 만들고 MD는 대체 경로로 둔다. 어떤 형식이든 실제 근거와 가정, 실패 경로는 구분한다.

핵심 설명에서는 한 장면과 값을 유지한다. 사용자 행동 → 처리·상태 변화 → 출력 → 실패 조건 → 현재 판단의 순서로 필요한 연결을 보여 준다. 본문은 그림의 번호를 따라가며 화살표가 이어지는 이유를 풀어 쓴다. ‘독립성·영속성·경계’ 같은 용어는 먼저 예에서 맡는 일을 설명한 뒤 이름을 붙인다. 장치가 없는 경우나 가까운 대안을 비교하되 가짜로 열등한 대안을 만들지 않는다. 예시가 있다고 충분한 것이 아니라, 예시가 주장과 다음 선택을 실제로 설명하는지 본다.

사람이 아는 C++·소유권·수명·상태 전이와 비교할 수 있으나 비유가 다른 지점을 밝힌다. 상세 보고에서는 핵심 인과 설명을 접힌 영역에 숨기지 않고 출처 표·부차 자료만 접는다.

## 이해 기준과 중단

현재 대상이 무엇을 하는지, 왜 필요한지, 실제 대안과 무엇이 다른지, 어떤 요구·조건·주체가 동작을 정하는지 연결한다. 하나의 핵심 원리를 적용해 관련 결과나 실패를 예상할 수 있으면 현재 판단으로 돌아간다. 모든 개념의 숙달이나 숫자 점수를 선언하지 않는다.

설명의 끝에 자동 복습 문제를 붙이지 않는다. 중요한 선택·결과 수용에서만 toolkit/understanding.md의 확인을 자연스럽게 통합한다. 사용자가 ‘모르겠다’고 하면 질문 수를 늘리기보다 막힌 전제·용어·화살표를 좁혀 설명한다. 깊이 요청을 시간 절약만으로 거절하지 않고 현재 작업에 미칠 시간을 밝혀 범위를 조정한다.
