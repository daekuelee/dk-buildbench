# 준비 과정의 일반 점검 기준

특정 회차의 회고·사례 대신 재사용할 규칙만 남긴다. 현재 절차는 SKILL과 ops를 따른다.

- 초기 업무 흐름과 지금 판단할 것을 먼저 보여 준다. 문서 길이를 줄이려고 필요한 이유를 지우거나, 상세 표를 다 읽어야 판단할 수 있게 만들지 않는다.
- 역할·업무·성공 기준은 현재 README·제공 자료·답에서 확인한다. 하네스의 협업 역할을 업무 역할로 대신 쓰지 않는다.
- 질문에는 이유와 확인 대상을 붙이고 바로 아래에 답할 자리를 둔다. 이미 답이 있는 질문은 반복하지 않는다. 큰 흐름·범위·성공 판단의 빈 곳부터 좁히며 고정 질문을 모두 소진하지 않는다.
- 환경은 필요한 읽기 확인부터 한다. 확인하지 못한 것과 미설치를 구분하고 키 값은 출력하지 않는다. 보호된 경로·플랫폼 설정을 바꾸어 제한을 우회하지 않는다.
- 초기 이해와 질문을 모든 자료 확인이 끝날 때까지 미루지 않는다. 분담은 필요하고 승인된 경우에만 쓰며 자료 담당은 관찰과 근거를 반환한다.
- 준비도는 출발을 돕는 내부 판단이며 공식 점수·이해도·품질 보장이 아니다. 전수 조사·전체 설계·구현 승인을 setup 완료와 섞지 않는다.
- 사람 원문과 AI 해석을 분리한다. 이미 채택한 선택은 재승인시키지 않고 새로운 판단만 자연어로 묻는다.
- 사용자의 문제 문장은 대신 작성하지 않는다. 설명·정리가 필요하면 별도 AI 해석으로 제공한다.
