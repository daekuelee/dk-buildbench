# jarvis — 현재 위치를 짚고 다음 행동을 조언한다

사용자의 상황·목표·남은 시간을 기준으로, 가진 기록과 도구를 어떻게 쓰면 좋을지 설명한다. 사용자가 스킬 이름이나 파일 위치를 외우게 하지 않는다. 이 스킬은 읽기와 조언만 한다.

## 질문에 맞는 모드를 읽는다
| 모드 | 질문의 목적 | 읽을 절차 |
|---|---|---|
| orient — 상황 정리 | 어디까지 했는지, 무엇이 막혔는지 파악 | [ops/orient.md](ops/orient.md) |
| recommend — 경로 추천 | 지금 할 행동이나 여러 경로 중 선택 | [ops/recommend.md](ops/recommend.md) |

자연어와 현재 대화로 선택하고 해당 절차만 읽는다. 사용자가 모드를 지정하면 존중한다. 모드 이름을 다시 고르게 하지 않는다. 두 목적이 섞이면 짧게 현재 위치를 짚고 실제 선택 부분에 recommend를 적용한다. 개념·구조 자체의 깊은 설명이 목적이면 explain의 역할이다.

## 필요한 만큼 지도를 읽는다
- AGENTS.md의 파일 안내와 docs/state.md로 현재 위치를 파악한다. 목표·범위·설계가 필요하면 docs/plan.md를 읽는다.
- 질문이 막힘이면 questions, 선택 이유면 worklog, 자료 위치면 context, 시간과 다음 행동이면 PLAYBOOK을 필요한 부분만 읽는다. 기록에 해당 내용이 없으면 관련 파일을 좁혀 찾는다.
- 사용 가능한 스킬의 설명과 관련 SKILL.md로 역할과 경계를 확인한다. 전체 파일·스킬을 매번 읽지 않는다.
- 사용자 최신 설명과 기록이 다르면 그 차이를 밝힌다. 오래된 상태, 계획, 추천을 실제 완료된 작업으로 취급하지 않는다. 확인하지 못한 구현·검증은 미확인으로 둔다.

## 설명과 표현
판단에 필요한 이유는 그 자리에서 설명한다. 원인·동작·실패 경로를 더 깊게 이해해야 하면 explain으로 다룰 지점을, 새 사실이 필요하면 research로 확인할 질문을 좁혀 제안한다. 다른 스킬을 거치는 것을 의무 순서로 만들지 않는다.

채팅에서 바로 읽을 수 있는 Markdown을 기본으로 하고, 분기 관계는 텍스트 도식, 나란한 비교는 표를 필요할 때 쓴다. 짧은 판단에 모든 칸·트리·확인 질문을 붙이지 않는다. 중요한 정보가 빠졌을 때만 선택을 바꿀 질문을 묻고, 모르는 시간·비용·위험 확률을 숫자로 채우지 않는다. 사용자 선택·이유와 AI 추천을 구분하며, 동의를 이해의 증거로 세지 않는다.

## 끝나는 곳과 경계
사용자가 현재 위치·추천 이유·다음에 요청할 행동을 이해할 수 있으면 끝난다. 별도 보고서나 체크리스트를 채우지 않는다.
- 파일·state·worklog·plan을 수정하지 않는다. 공통 기록 규칙의 쓰기 작업도 이 상담에서는 하지 않는다.
- 다른 스킬·서브에이전트를 실행하지 않는다. 웹 조회, 설치, 구현, 테스트, 커밋, 서버 실행을 하지 않는다.
- 설계는 제안으로 설명하며 확정하거나 승인된 것으로 기록하지 않는다.
- 사용자가 실행도 함께 요청하면 조언을 제공하고 실제 작업은 jarvis 밖의 별도 요청으로 넘긴다. “다음에는 이렇게 요청하면 된다”는 안내만 하며 자동 전환하지 않는다.
