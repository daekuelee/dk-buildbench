# recommend — 근거로 다음 경로를 추천한다

## 판단 재료를 모은다
지금 정할 행동과 목표를 잡고, 확인된 정보·미확인·가용 시간과 도구·주요 위험을 관련 기록에서 읽는다. 병목이 요구 미확인인지, 개념 이해인지, 실행·검증 문제인지 짚는다. 이미 승인한 행동을 다시 선택지로 돌리지 않는다.

## 추천을 비교 가능하게 보여 준다
1. 추천과 이유를 먼저 한 문장으로 보인다. 핵심 근거가 부족하면 잠정 추천이라고 밝히거나, 선택 전에 필요한 확인을 다음 행동으로 추천한다.
2. 판단에 쓰인 상황·정보·시간·위험을 가까이 모아 보여 준다. 긴 기록을 머릿속에서 합쳐야 추천을 이해하는 형태를 피한다.
3. 실제로 가능한 대안이 있으면 같은 목표·필수 조건에서 얻는 것과 비용·위험을 비교한다. 근거 있는 경로만 남기며 개수를 맞추려고 대안을 만들지 않는다. 시간에 비해 준비가 길어졌다면 작은 동작 확인이나 범위 축소도 검토한다.
4. 중요한 추천 근거를 `출처의 확인 내용 → 이 선택에 주는 영향 → 추천`으로 연결한다. 파일:줄·기록 위치·실행 결과를 해당 주장 옆에 둔다. 출처 목록만 나열하지 않고 사실과 AI 추론을 구분한다. 확인하지 않은 자료를 조사했다고 쓰지 않는다.
5. 어떤 조건이면 추천이 바뀌는지, 그 조건을 무엇으로 확인할지 보인다. 선택이 남았으면 사용자가 정할 한 가지를 묻고 끝낸다. 이미 결정했으면 재승인이나 새 프롬프트를 요구하지 않는다.

## 분기를 보일 때
Markdown 텍스트 도식으로 현재 상태에서 갈리는 경로와 추천을 표시한다. 이어지는 결과가 지금 선택에 영향을 줄 때만 다음 분기를 보인다. 미래의 전체 작업을 미리 트리로 채우지 않는다.

```text
현재: [목표에 비해 확인된 것 / 남은 불확실성]
  ├─ A. [실제 경로] — 얻는 것 / 비용·위험
  └─ B. [실제 경로, 추천이면 표시] — 얻는 것 / 비용·위험
       ├─ [확인 결과] → [다음 행동]
       └─ [다른 결과] → [추천을 바꿀 행동]
```

예문의 빈칸은 실제 근거로 대체하고 불필요한 가지는 생략한다. 단순한 선택은 문장만으로 충분하다. 상세 근거가 길어져도 추천·핵심 차이·전환 조건은 채팅에서 볼 수 있게 한다. 기존 SKILL.md의 읽기·조언 경계를 유지하고 추천한 조사·구현을 자동 실행하지 않는다.
